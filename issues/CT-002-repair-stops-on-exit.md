# CT-002 退出应用后修复程序也停止

依据：实测案例。核对日期：2026-10-21。平台：Windows，应用管理的执行会话。

## 问题

恢复程序已启动并等待 Codex 退出。正常退出并重新进入后，项目仍未恢复，结果记录停在 `waiting_for_exit`。

## 原因与证据

本例的修复程序随宿主执行会话结束，尚未进入写回阶段。仅安排一个后台等待任务不等于它能独立存活。Windows 沙箱的子进程生命周期还取决于实现及运行方式，不能承诺所有 detached 进程都会保留。[官方 Windows 沙箱说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)

## 解决方案

先从文件资源管理器或应用之外的独立终端启动修复器，再正常退出目标应用；保持独立修复窗口打开。不要为了让进程存活而关闭系统安全机制。

修复器应先验证清单和备份条件，确认应用停止后才写入，重新读取验证成功再打开应用。`dry_run_passed`、`waiting_for_exit` 与实际写入完成必须分开记录。

## 验收

检查写回后目标文件，而不是仅看等待程序被启动。再确认应用能读到项目和抽查聊天的归属。独立程序如果仍被终止，停止重试同一执行方式，保留日志并更换明确独立的启动环境。

## 回退与限制

没有写入时无需回退配置；写入中断后先检查目标文件是否完整，再决定从备份恢复。单纯延长等待时间不能解决进程被结束的问题。
