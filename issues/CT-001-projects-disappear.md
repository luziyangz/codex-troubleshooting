# CT-001 项目消失 旧聊天集中到最近

依据：实测案例。核对日期：2026-10-21。平台：Windows。应用版本：本案例未完整记录，不限定所有版本均有相同结构。

## 问题

重新打开应用后，本地项目不出现在侧栏，原项目聊天集中到“最近”。侧栏实际上已按项目分组；抽查旧聊天和原项目目录仍存在。

## 原因与证据

已确认的直接原因：启动日志记录 `Failed to load global state`，并提示 `Unexpected token '\u0000'`；本地状态无法正常解析，项目列表及原有聊天归属没有正常加载。后续读取到的项目缓存为空，但数据库仍保留项目定义及根目录。

是什么导致文件包含无效空字符，仍然未知。不能将本例自动归因于升级、强制退出、第三方配置工具或模型服务商。

## 解决方案

1. 用 [快速分诊](../docs/triage.md) 排除账号、主机、分组、过滤和归档因素。
2. 备份现场；只读检查状态 JSON、项目定义、根目录与启动错误。
3. 从本次有效记录建立恢复清单，在副本中验证；保留已有正确值。
4. 由独立程序在应用退出后合并配置，再重新打开并验收。详细步骤见 [恢复 SOP](../docs/recovery-sop.md)。

少数入口被移除时，先按 [官方说明](https://learn.chatgpt.com/docs/reference/troubleshooting#remove-a-project-from-the-sidebar) 重新添加原目录，不必直接改状态文件。

## 验收与实测结果

本次配置恢复了 9 个项目记录、24 条聊天归属。应用接口重新列出项目，抽查旧聊天返回对应项目标识。SQLite 的 `threads.project_id` 当时仍为空，不能声称该字段完成同步；也没有逐条人工打开全部聊天或完成第二次重启验收。

这些数量仅是本案例观察，不是工具的固定输入。验收应同时看项目、抽查聊天与重启持久性，不能只看 JSON 合法。

## 回退与限制

应用关闭后，使用明确对应的修复前快照撤销修改。没有项目定义、聊天本体丢失、版本结构不匹配或归属冲突时，不继续自动写回。通用工具提供线索，不替代数据恢复判断。
