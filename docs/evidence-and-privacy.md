# 证据与公开材料规范

## 证据等级

| 标记 | 含义 |
| --- | --- |
| 实测案例 | 有明确操作环境、现象、执行过程及结果 |
| 官方流程整理 | 引用已打开核对的官方文档；不声称本仓库实测 |
| 待验证 | 只有报告或推测，不能标记通用有效 |

原因另标“已确认”“推测”或“未知”。例如 JSON 解析失败可以由日志确认，但是什么导致文件损坏仍可能未知。把更新、强退、模型切换等发生在前的事件直接写成根因，会误导后续修复。

## 公开材料

本地状态、诊断备份和日志先留在本机。公开 Issue 只提交系统与应用版本、错误类别、执行步骤和已脱敏的摘要。不要附带 `auth.json`、token、Cookie、完整配置、数据库、真实聊天标识、聊天正文、私人仓库名和个人绝对路径。

只读工具默认仅输出计数、结构与错误类别，不自动读取日志、扫描浏览器、读取凭据或联网。它生成的摘要可先自行审阅后再分享；是否发布始终由使用者决定。

## 版本与结果

没有记录版本就写“未记录”，不要补一个推测版本。测试通过必须说明是合成测试、真实只读检查，还是实际写回恢复。Windows 案例不能直接表述为 macOS、Linux 已验证。

## 首次案例的公开范围

保留故障时间、错误类别、恢复项目与关联数量作为案例观察；移除原路径、原项目名、真实项目及聊天标识、原配置和恢复包。仓库中的示例数据全部为合成记录。
