GitHub 保存问题条目、证据边界与更正记录。外部平台的文章帮助不同读者理解问题，并链接回对应条目。仓库里的三份文章是待审核稿，尚未发布到三平台。

## 每次发布

1. 先更新 GitHub 对应 CT 条目，保留核对日期、适用版本和未知项。
2. 选定文章依据的提交或版本，核对引用与代码是否一致。
3. 使用文章初稿，按目标平台调整标题、开头、篇幅、图表和代码展示。
4. 发布前检查平台当时的原创、转载、AI 辅助内容、外链和社区规则，按实际情况声明；不提前承诺审核通过。
5. 在已登录的账号下导入或粘贴内容，预览代码块、表格和链接。知乎是否采用回答或文章，按实际问题与账号情况决定。
6. 获得明确的本次平台发布指令后提交；若出现登录验证、验证码或平台确认，由账号持有人配合处理。
7. 打开实际发布页面核对内容和可见性，把标题、URL、日期、来源版本记入 [发布记录](publication-ledger.md)。草稿保存和审核中不记为已公开。
8. 原结论需要更正时，先改 GitHub，再同步各平台；记录更正日期，避免文章继续引导读者使用过时脚本。

平台登录、编辑器能力和发布规则可能变化，首版不提供承诺一键自动发布三平台的脚本。可以逐平台协助，但不需要为分享内容先开放不必要的账号权限。
